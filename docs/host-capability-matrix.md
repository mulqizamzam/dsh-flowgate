# Host capability matrix

Flowgate never guesses a host API. Every capability the plugin relies on is
recorded here with the evidence used to verify it and the product guarantee that
evidence permits. The matrix is generated by `lib/host.js` and asserted by
`tests/host-capabilities.test.mjs` and `tests/live-host-verification.test.mjs`, so
this document cannot drift from the code without a failing gate.

Two summaries are recorded because they describe two different situations:

- **Live mount:** `8 verified, 2 unsupported, 0 unknown`.
- **Bare declarations (no live `ctx.commands`/`ctx.skills`):** `6 verified, 4 unsupported, 0 unknown`.

Counts in the table are produced by `capabilitySummary(hostCapabilityMatrix())`;
the two recorded strings above are asserted verbatim by
`tests/host-capabilities.test.mjs`.

## Enforcement level

`enforcementRecord()` returns:

- `level: 'validated'` — a stage artifact is accepted only after the contract's
  artifact, evidence, and gate checks pass. This is enforcement of the *record*,
  not a verified runtime lock on the agent loop.
- `pre_step: 'available_not_used'` — the host declares `agent/pre-step`, and
  Flowgate deliberately does not subscribe to it. Rejecting a step would also
  reject the remediation steps a failed gate requires, so the hook cannot be used
  honestly as a gate lock.
- `limitations` — three sentences naming what is not enforced. They are rendered
  in every `--dry-run`, `--status`, and `--report` output.

`tests/live-host-verification.test.mjs` asserts that `lib/index.js` contains no
`'agent/pre-step'` subscription and that no report ever claims `"enforced"`.

## Live verification path

The supported live path is a real cordis `Context` with:

1. `SessionStore`, `CommandRuntime`, `SkillRegistry`, and a
   `FileSystemSkillProvider` mounted over `assets/skills`.
2. An agent object that records `steer` calls.
3. `flowgate` mounted with an explicit `stateDir`.

On that path the plugin registers nine commands, resolves real skill bodies,
records real `session/event` tool results as observations, and accepts an
assistant message containing an artifact as stage output. All of it is asserted in
`tests/live-host-verification.test.mjs`, which is the gate that proves the
capability claims above rather than restating them.

If the installed host stops declaring one of the checked needles, the entry flips
to `unsupported`, `tests/host-capabilities.test.mjs` fails, and this document must
be updated in the same change.
